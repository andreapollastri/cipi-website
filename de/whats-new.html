Die Schlagzeilen
01 — Die Schlagzeilen

Vierundzwanzig Gründe,
heute Abend zu aktualisieren.

Alles Cipi 5 addiert auf einen Blick. Kacheln getaggt since 5.0 versandt mit Cipi 5; since 5.2 ist neu in dieser Version. Tippen Sie auf eine beliebige Kachel, um zu den Docs zu springen.

Schlagzeilenfunktion
01 since 5.0

Laravel Octane
auf FrankenPHP.

Starten Sie das Framework einmal und behalten Sie es im Speicher. Es laufen Octane-Apps und klassische PHP-FPM-Apps Seite an Seite auf demselben Server – Nginx stellt einen Proxy für den Octane-Prozess dar, Supervisor behält ihn lebendig, jedes Deployment lädt es sauber neu.

cipi app create myapp --domain=myapp.com --octane
02 since 5.0

PostgreSQL, neben MariaDB.

Zwei Motoren auf einer Box. Wählen Sie pro App aus oder legen Sie einen serverweiten Standard fest – Umgebung, Backups und Wiederherstellungen folgen.

cipi db install pgsql
03 since 5.0

Laravel Horizon

Überwacht und bei jedem Release neu gestartet.

cipi worker horizon enable
04 since 5.0

Laravel Reverb

WebSockets seit 5.1.2 produktionsreif: generierte Zugangsdaten, wss:// vom Zertifikat, ein Proxy der /appointments nicht mehr verschluckt.

cipi app reverb enable
05 since 5.0

Ihr Frontend baut auf dem Server auf

Führen Sie den Build innerhalb der Version direkt nach den Abhängigkeiten aus. Fail-Closed, also kaputtes Vermögen gelangen nie in die Produktion – und kompilierte Dateien erreichen nie Ihr Repository.

cipi app edit myapp --node-build='npm ci && npm run build'
06 since 5.0

Scheduler-Schalter

Cron pro App ein- oder ausschalten, ab CLI.

cipi schedule on myapp
07 since 5.0

Konvertieren Sie FPM ⇄ Octane

Wechseln Sie die Laufzeit einer Live-App in beide Richtungen.

cipi app convert myapp --to=octane
08 since 5.0

Ein Snapshot vor jeder riskanten Migration

Melden Sie sich pro App oder pro Deployment an und sichern Sie die Datenbank für Cipi, bevor das Release herauskommt. Ein schlechtes Die Migration wird wiederherstellbar statt tödlich.

cipi deploy myapp --snapshot-required
09 since 5.0

Sofortige Inszenierung

Klonen Sie eine Produktions-App auf eine neue Domain.

cipi app clone myapp --domain=stage.myapp.com
10 since 5.0

Ressourcengrenzen

Keine App kann die Box mehr aushungern lassen.

cipi app limits myapp --memory-limit=256M
11 since 5.0

Wildcard-Zertifikate, ohne den HTTP-Tanz

Stellen Sie eine Cloudflare DNS-01-Herausforderung aus und erneuern Sie sie, wenn ein öffentlicher HTTP-Endpunkt nicht vorhanden ist Option. HTTP-01 bleibt die Standardeinstellung.

cipi ssl install myapp --dns=cloudflare --wildcard
12 since 5.0

Health-Checks

Alle 5 Minuten. E-Mail nach 3 Fehlern.

cipi health set myapp --url=…
13 since 5.0

Ein kanonischer Host

www oder apex, Alias ​​und 301 für Sie.

cipi www force-to-root myapp
14 since 5.0

HTTPS erneut erzwingen

Stellen Sie die Weiterleitung wieder her, ohne sie erneut auszustellen.

cipi ssl force myapp
15 since 5.1

Backup-Profile, kein fest codierter Auftrag

Umfang, Zeitplan, Ziel und Aufbewahrung pro Profil. Als nächstes folgt eine 30-minütige Kopie der lokalen Datenbank zu einer verschlüsselten nächtlichen Vollkopie am S3. Getrennt gespeicherte Dateien und Datenbanken; Mieter Von der Engine erkannte Datenbanken. Die Aufbewahrung ist Pflicht.

cipi backup profile add
16 since 5.1

Geführte php.ini

Sehen Sie sich jedes abstimmbare Element an und erfahren Sie, welche Ebene es festgelegt hat. Schreibt FPM und CLI zusammen, serverweit oder --app=. Nur Whitelist.

cipi ini set upload_max_filesize=50M
17 since 5.1

cipi.yml reist mit dem Code

Aliase, PHP, zusätzliche Datenbanken, Worker, Healthcheck und Backups – im Repo. plan, apply, auto nach jedem Einsatz. Fail-Closed: Es erstellt niemals eine App und führt niemals einen Shell-Befehl aus.

cipi yml generate myapp
18 since 5.1

Unbekannter Host → 444

Eine Anfrage, die keiner App entspricht, landete auf einem zufälligen Vhost. Jetzt :80 und :443 Schließen Sie es mit einer leeren Antwort.

cipi nginx default-server on
19 since 5.1

Zustand nach dem Deployment, optionales Rollback

Das Release, die gerade online gegangen ist, wird sofort geprüft – nicht nach drei fünf Minuten Misserfolge. Aktivieren Sie die automatische Wiederherstellung. Migrationen werden nicht rückgängig gemacht; heißt es in der E-Mail also.

cipi health set myapp --rollback-on-unhealthy
20 since 5.1

Platzhalter-Aliase

Mandantenfähige Apps benötigen *.example.com. Nginx konnte schon; Cipi akzeptiert jetzt es.

cipi alias add myapp '*.example.com'
Sicherheits-Release
21 since 5.2

CrowdSec, Engine
und Bouncer.

Optionale IP-Reputation, die die Logs liest, die Ihre vhosts wirklich schreiben. Die Engine kommt mit einem registrierten Firewall-Bouncer — Decisions ohne Bouncer sperren nämlich gar nichts. Sie verweigert den Start hinter einem unkonfigurierten Reverse Proxy und nimmt die SSH-Sitzung, aus der Sie sie aktivieren, in die Allowlist. Es gibt keine WAF.

cipi crowdsec enable
22 since 5.2

Ein Weg zurück hinein

Ein TLS-Listener auf hohem Port und ein Einmal-Token. Ein GET nimmt Ihre IP in die Allowlist und entsperrt sie in CrowdSec und fail2ban. Kein Login, kein SSH-Key.

cipi crowdsec rescue rotate
23 since 5.2

Nächtliche Integritätsprüfung

sha256 des laufenden Release gegen das beim Deploy geschriebene Manifest, danach ClamAV ausschließlich über die Upload-Verzeichnisse. Um 04:40, jede Nacht.

cipi scan enable
24 since 5.2

Tab-Vervollständigung, für Sie installiert

bash und zsh, geschrieben von setup.sh und jedem self-update. Verben, Unterbefehle, Flags und Ihre App-Namen. Keine Dotfile zu bearbeiten.

cipi app <TAB>

02 – Der Wandel

Was früher Arbeit war,
ist jetzt eine Flagge.

Das ehrliche Vorher und Nachher. Links ist, was der Betrieb dieser Dinge Sie früher gekostet hat. Rechts ist Cipi 5, markiert nach Release.

Laufzeit since 5.0 PHP-FPM für alles → FPM oder Octane auf FrankenPHP, wählbar pro App
Queues since 5.0 Nackte Queue-Worker, manuell neu gestartet → Horizon unter Supervisor, bereitstellungsfähig
Websockets since 5.0 Erstellen Sie Ihren eigenen Port, Proxy und Dienst → Reverb in einem Befehl aktiviert, SSL inklusive
Datenbanken since 5.0 MariaDB, nimm es oder lass es → MariaDB und PostgreSQL, pro App
Frontend since 5.0 Übertragen Sie kompilierte Assets oder integrieren Sie CI → Der Node-Build wird innerhalb der Version ausgeführt, bei Fail-Closed
Migrationen since 5.0 Deploy und hoffen → Automatischer Snapshot vor Erscheinen des Releases
Inszenierung since 5.0 Erstellen Sie eine zweite App manuell neu → Ein Klonbefehl, Datenbank optional
Platzhalter since 5.0 Manuelle DNS Herausforderung bei jeder Erneuerung → DNS-01 mit Cloudflare, automatisiert
Überwachung since 5.0 Eine Dienstleistung eines Drittanbieters und deren Rechnung → Health-Checks alle fünf Minuten, integriert
Laute Apps since 5.0 Eine App könnte den Server lahmlegen → Harte Obergrenzen für Worker, Kinder und Erinnerung
Backups since 5.1 Ein fest programmierter nächtlicher Job → Profile, clientseitig AES-256, verifizieren, verwaltet cron
php.ini since 5.1 FPM-Dateien von Hand bearbeiten; CLI ignoriert → cipi ini für beide SAPIs, serverweit oder pro App
App-Konfiguration since 5.1 Per SSH auf jedem Server neu erstellen → cipi.yml in Git, beim Deployment angewendet
Unbekannter Host since 5.1 Auf einem zufälligen Vhost gelandet → Leerer 444-Standardserver
Defektes Deployment since 5.1 Warten Sie fünfzehn Minuten auf eine Gesundheits-E-Mail → Sofortige Prüfung nach dem Deployment, optionales Rollback
Aliase since 5.1 Nur genaue Namen → *.example.com Platzhalter
Angreifer since 5.2 fail2ban, und erst im Nachhinein → CrowdSec-Decisions, von einem registrierten Bouncer verworfen
Ausgesperrt since 5.2 Die Rescue-Konsole des Anbieters → Einmal-Token auf einem Rescue-TLS-Port
Manipulation since 5.2 Auffallen, wenn etwas komisch aussieht → Nächtliches sha256 gegen das Deploy-Manifest
Die CLI since 5.2 Jedes Verb auswendig → TAB vervollständigt Verben, Flags und App-Namen

04 — Since 5.0.6

Panel API, GUI
und Automatisierung.

Serververwaltung über REST API und optionales Web GUI – plus nicht interaktive Flags für Skripte. Erfordert cipi self-update zu 5.1.0 und Panel API 1.20.

PHP Nur SSH-Versionsverwaltung → GET /api/php, installieren, entfernen, Standard festlegen
SSH-Schlüssel Nur-Terminal-Schlüsseladministrator → REST + GUI für cipi Benutzerschlüssel
Dienstleistungen Manuelle Systemsteuerung → GET /api/services und starten Sie vom Panel aus neu
SMTP Nur interaktiver Assistent → REST + cipi smtp configure --host=…
Gesundheit Schecks nur für CLI → REST pro App + --json auf CLI
API Zugang Jede IP mit einem Token → Optionale IP-Whitelist aktiviert api/* und /mcp
Webhooks Erstellen Sie es neu, indem Sie das Repo erneut bearbeiten → cipi app webhook recreate [--rotate-secret]
Selbstaktualisierung Könnte bei API/GUI Composer Schritt hängen bleiben → 5.0.14–5.0.17 — zeitgesteuerte Aktualisierungen des Packagist-/Tarball-Panels
Panel GUI HTTP 500 nach Upgrade/Soft-Update → 5.0.18 — kein Composer-Symlink draußen open_basedir

Eine Linie steht dazwischen
Du und alles davon.

Führen Sie den Updater aus und Cipi erstellt Vhosts, Pools, Deployer-Vorlagen und App-Metadaten an Ort und Stelle neu – ohne Ihren Code oder Ihre Daten zu berühren.

  • Alles Neue ist Opt-in – Octane, Horizon, Reverb, PostgreSQL, Snapshots, Gesundheit Überprüfungen, Backup-Profile, cipi.yml auto und Rollback nach dem Deploy, CrowdSec und der nächtliche Scan bleiben ausgeschaltet bis du fragst.
  • Ihre PHP-FPM-Apps laufen genauso weiter, wie sie sind, neben allen neuen Octane Nachbarn.
  • Fresh-Server bekommen alles mit dem üblichen Installationsprogramm sofort einsatzbereit.
