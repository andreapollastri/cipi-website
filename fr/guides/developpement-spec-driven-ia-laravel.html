Développement basé sur les spécifications avec Agents IA: le playbook Laravel

Par Andrea Pollastri · Dernière mise à jour : 4 août 2026 · lecture gratuite, pas de paywall

Les agents IA écrivent désormais une part significative du code de production. Les équipes qui obtiennent des résultats durables ne sont pas celles qui disposent des meilleures invites : ce sont celles qui disposent des meilleures spécifications, des garde-corps les plus serrés et des agents d'outillage qui peuvent opérer en toute sécurité. Voici le playbook, édition Laravel.

De la saisie semi-automatique aux agents

L’arc de 2023 à 2026 est facile à résumer : les complétions sont devenus des chats, les chats sont devenus des agents qui éditent des branches entières, exécutez des tests et ouvrez des demandes d'extraction. Le goulot d'étranglement s'est déplacé avec lui - de "le modèle peut-il écrire du code ?" à "le modèle sait-il ce que nous voulons réellement et ce qu'il est permis de faire toucher ?". C'est un problème de contexte et d'autorisations, pas un problème de modèle. Deux pratiques y répondent : spécifications et MCP.

Spécifications sur les vibrations

Le « Codage Vibe » — invitant un agent fonctionnalité par fonctionnalité avec l'intention de vivre dans l'historique des discussions — produit code qui fonctionne aujourd'hui et qui n'est pas maintenable dans six mois, carle pourquoi s'évapore lorsque le chat se ferme. Le développement basé sur les spécifications inverse ce qui suit :

  • Les spécifications sont des artefacts dans le référentiel, versionné à côté du code qu'ils décrivent - pas invites perdues dans une barre latérale.
  • Les critères d’acceptation passent en premier et traduire directement en tests Pest : la spécification définit "terminé" avant que l'agent n'écrive une ligne.
  • Les agents implémentent par rapport aux spécifications, les humains examinent par rapport aux spécifications, et la dérive devient visible au lieu d'être silencieux.
  • La spécification survit à la session. Six mois plus tard, un nouveau développeur – ou un nouvel agent – lit l'intention, les contraintes et les décisions en un seul endroit.

Dans le monde Laravel, Larapilot présente cela sous la forme d'un flux de travail de produit basé sur les spécifications qui vit dans votre projet Laravel - spécifications, décisions et la livraison des artefacts dans le dépôt, où les agents et les humains les trouvent tous deux. Pour un argument plus profond sur pourquoi le contexte dans le dépôt est ce qui maintient un produit en vie au cours de la première année, essai d'Andrea Pollastri "Construire un SaaS qui survit à sa deuxième année" vaut votre temps.

MCP : le standard qui a rendu les agents utiles

Le Protocole de contexte de modèle est l'USB-C des outils d'IA : un protocole ouvert à travers lequel les agents découvrent et appellent des outils (bases de données, navigateurs, outils de suivi des problèmes, serveurs) au lieu de gratter l'écran ou des plugins sur mesure. Pour une équipe Laravel, les serveurs MCP intéressants sont ceux qui touchent votre pipeline de livraison :

  • Votre cadre : introspectez les itinéraires, les schémas et les tâches pour que l'agent arrête de deviner.
  • Votre infrastructure : c'est là que ça devient réel — Cipi expédie un double serveur MCP(global et par application), donc un IDE ou un agent compatible MCP peut créer des applications, déclencher des déploiements, gérer SSL et des bases de données sur votre VPS via un API structuré et autorisé au lieu d'un SSH brut. Le Cipi Forfait Agent ajoute un point de terminaison MCP dans l'application sur Laravel côté.
  • Vos portails de qualité : les agents qui peuvent exécuter la suite de tests et lire les résultats du CI se ferment leur propre boucle de rétroaction.

Des garde-corps qui fonctionnent réellement

  • Les tests sont le contrat. Les agents expédient plus rapidement que les humains ne peuvent examiner ligne par ligne ; les tests d'acceptation dérivés de la spécification sont ce que signifie « correct ».
  • CI est l'arbitre. Audit Pint, Larastan, Pest et composer exécuté sur chaque agent PR, aucune exception - la même chose canalisation les humains obtiennent.
  • Moindre privilège pour les agents. Jetons API étendus, serveurs MCP avec outil explicite listes autorisées et aucun secret de production dans l'environnement de l'agent. Un agent qui se déploie via Les MCP/API de Cipi peuvent se déployer – et rien d'autre.
  • Examen humain pour le différentiel sensible :authentification, paiements, migrations et tout ce qui touche Les informations personnelles ont toujours des yeux humains.
  • La restauration reste à une commande — déploiements de modèles de versions et instantanés de pré-déploiement signifie qu'une erreur d'agent est un incident, pas une catastrophe.

Une boucle concrète entre les spécifications et la production

  1. Écrivez la spécification (problème, contraintes, critères d'acceptation) en tant qu'artefact de dépôt - Larapilot lui donne de la structure.
  2. L'agent met en œuvre sur une branche éphémère, en utilisant les outils MCP pour introspecter l'application et exécutez des tests localement.
  3. CI ouvre la porte à plein régime — style, analyse statique, tests, audit de sécurité.
  4. Un humain évalue par rapport aux spécifications, pas contre les vibrations.
  5. La fusion avec le principal déclenche le déploiement webhook (zéro temps d'arrêt via Cipi), contrôles de santé confirmer, les exceptions sont surveillées pendant les premières minutes (Google si vous vous auto-hébergez).
  6. La spécification est mise à jour avec ce qui a été réellement décidé - fermer la boucle contextuelle pour la prochaine session, humaine ou agent.

Questions fréquemment posées

Qu’est-ce que le développement axé sur les spécifications en une phrase ?

Rédaction de spécifications versionnées (problème, contraintes, critères d'acceptation) en tant qu'artefacts de référentiel que les agents d'IA implémentent et que les humains examinent, de sorte que l'intention survit plus longtemps que n'importe quelle session de discussion.

Qu'est-ce que MCP (Modèle Context Protocol) ?

Un protocole ouvert qui standardise la manière dont les agents IA découvrent et appellent des outils externes (bases de données, navigateurs, serveurs, API) afin que tout agent compatible MCP puisse utiliser n'importe quel serveur MCP sans intégrations personnalisées. Cipi, par exemple, expose la gestion du serveur (applications, déploiements, SSL, bases de données) en tant qu'outils MCP.

Les agents IA remplaceront-ils les développeurs Laravel ?

Le travail évolue plutôt que de disparaître : moins de saisie ligne par ligne, plus de spécification, de révision et de propriété de l'architecture et de la production. Les développeurs qui rédigent des spécifications claires et construisent des garde-fous solides sont multipliés par des agents ; la partie code uniquement du travail est ce qui rétrécit.

Comment laisser un agent IA se déployer en toute sécurité ?

Ne donnez jamais aux agents des secrets SSH ou de production bruts. Acheminez leur accès via des interfaces limitées et révocables - un serveur MCP ou REST API avec des autorisations explicites, comme celles de Cipi - et contrôlez chaque modification derrière CI et le modèle de versions, de sorte que tout déploiement soit réversible en une seule commande.

Le développement basé sur les spécifications fonctionne-t-il avec les bases de code existantes ?

Oui, commencez par rédiger les spécifications du prochain changement, pas de l'ensemble du système. Chaque spécification documente une tranche du comportement prévu, et l'archive se transforme en une documentation vivante exactement là où les agents et les nouveaux membres de l'équipe en ont besoin.
