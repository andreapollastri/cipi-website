Les gros titres
01 — Les gros titres

Vingt raisons de
mise à jour ce soir.

Tout ce que Cipi 5 ajoute, en un coup d'œil. Tuiles taguées since 5.0 livré avec Cipi 5 ; since 5.1 est nouveau dans cette version. Appuyez sur n’importe quelle vignette pour accéder aux documents.

Fonctionnalité de titre
01 since 5.0

Laravel Octane
sur FrankenPHP.

Démarrez le framework une fois et conservez-le en mémoire. Les applications Octane et les applications PHP-FPM classiques s'exécutent côte à côte sur le même serveur — Nginx proxys du processus Octane, Supervisor le conserve vivant, chaque déploiement le recharge proprement.

cipi app create myapp --domain=myapp.com --octane
02 since 5.0

PostgreSQL, à côté de MariaDB.

Deux moteurs sur une seule boîte. Choisissez par application ou définissez une valeur par défaut à l'échelle du serveur : environnement, sauvegardes et les restaurations suivent.

cipi db install pgsql
03 since 5.0

Laravel Horizon

Supervisé et redémarré à chaque version.

cipi worker horizon enable
04 since 5.0

Laravel Reverb

WebSockets enfin utilisables depuis 5.1.2 : identifiants générés, wss:// d'après le certificat, un proxy qui n'avale plus /appointments.

cipi app reverb enable
05 since 5.0

Votre frontend s'appuie sur le serveur

Exécutez la build dans la version, juste après les dépendances. Actifs fermés en cas de défaillance, donc cassés n’atteignez jamais la production – et les fichiers compilés n’atteignent jamais votre référentiel.

cipi app edit myapp --node-build='npm ci && npm run build'
06 since 5.0

Commutateur de planificateur

Cron activé ou désactivé par application, à partir du CLI.

cipi schedule on myapp
07 since 5.0

Convertir FPM ⇄ Octane

Changez d'environnement d'exécution sur une application en direct, dans les deux sens.

cipi app convert myapp --to=octane
08 since 5.0

Un instantané avant chaque migration risquée

Inscrivez-vous par application ou par déploiement et Cipi vide la base de données avant la sortie de la version. Un mauvais la migration devient récupérable au lieu d’être fatale.

cipi deploy myapp --snapshot-required
09 since 5.0

Mise en scène instantanée

Clonez une application de production sur un nouveau domaine.

cipi app clone myapp --domain=stage.myapp.com
10 since 5.0

Limites des ressources

Aucune application ne peut plus affamer la boîte.

cipi app limits myapp --memory-limit=256M
11 since 5.0

Certificats Wildcard, sans la danse HTTP

Émettez et renouvelez via un défi Cloudflare DNS-01 lorsqu'un point de terminaison HTTP public n'est pas un choix. HTTP-01 reste la valeur par défaut.

cipi ssl install myapp --dns=cloudflare --wildcard
12 since 5.0

Bilans de santé

Toutes les 5 minutes. Email après 3 échecs.

cipi health set myapp --url=…
13 since 5.0

Un hôte canonique

www ou apex, alias et 301 pour vous.

cipi www force-to-root myapp
14 since 5.0

Renforcer HTTPS

Restaurez la redirection sans la réémettre.

cipi ssl force myapp
15 since 5.1

Profils de sauvegarde, pas une tâche codée en dur

Portée, calendrier, destination et rétention par profil. Une copie de la base de données locale de 30 minutes ensuite vers une copie complète nocturne cryptée le S3. Fichiers et bases de données stockés séparément ; locataire bases de données découvertes à partir du moteur. La conservation est obligatoire.

cipi backup profile add
16 since 5.1

php.ini guidé

Voir chaque paramètre réglable et quelle couche l'a défini. Écrit FPM et CLI ensemble, à l'échelle du serveur ou --app=. Liste blanche uniquement.

cipi ini set upload_max_filesize=50M
17 since 5.1

cipi.yml voyage avec le code

Alias, PHP, bases de données supplémentaires, travailleurs, contrôle de santé et sauvegardes — dans le dépôt. plan, apply, auto après chaque déploiement. Fermé en cas d'échec : il ne crée jamais d'application et n'exécute jamais de commande shell.

cipi yml generate myapp
18 since 5.1

Hôte inconnu → 444

Une requête ne correspondant à aucune application utilisée pour atterrir sur un hôte virtuel aléatoire. Maintenant :80 et:443 fermez-le avec une réponse vide.

cipi nginx default-server on
19 since 5.1

État de santé post-déploiement, restauration facultative

La version qui vient d'être mise en ligne est examinée immédiatement, pas après trois minutes de cinq minutes. échecs. Inscrivez-vous pour le restaurer automatiquement. Les migrations ne sont pas annulées ; l'e-mail dit donc.

cipi health set myapp --rollback-on-unhealthy
20 since 5.1

Alias génériques

Les applications multi-locataires ont besoin *.example.com. Nginx le pourrait déjà ; Cipi accepte désormais ça.

cipi alias add myapp '*.example.com'

02 — Le changement

Ce qui était du travail,
est maintenant un drapeau.

L’avant et l’après honnête. Reste à savoir ce que vous coûtait la gestion de ces choses. La droite est Cipi 5, étiqueté par version.

Durée d'exécution since 5.0 PHP-FPM pour tout → FPM ou Octane le FrankenPHP, choisi par application
Files d'attente since 5.0 Travailleurs de file d'attente nue, redémarrés manuellement → Horizon sous Supervisor, compatible avec le déploiement
Prises Web since 5.0 Déployez votre propre port, proxy et service → Reverb activé en une seule commande, SSL inclus
Bases de données since 5.0 MariaDB, à prendre ou à laisser → MariaDB et PostgreSQL, par application
Front-end since 5.0 Valider les actifs compilés ou intégrer CI → La construction du nœud s'exécute dans la version, fermée en cas d'échec
Migrations since 5.0 Déployer et espérer → Instantané automatique avant la sortie de la version
Mise en scène since 5.0 Reconstruire une deuxième application à la main → Une commande de clonage, base de données facultative
Caractères génériques since 5.0 Défi manuel DNS à chaque renouvellement → DNS-01 avec Cloudflare, automatisé
Surveillance since 5.0 Un service tiers et sa facture → Contrôles de santé toutes les cinq minutes, intégrés
Applications bruyantes since 5.0 Une application pourrait faire tomber le serveur → Des plafonds stricts pour les travailleurs, les enfants et la mémoire
Sauvegardes since 5.1 Un travail de nuit codé en dur → Profils, côté client AES-256, vérification, gérés cron
php.ini since 5.1 Modifier manuellement les fichiers FPM ; CLI ignoré → cipi ini pour les deux SAPI, à l'échelle du serveur ou par application
Configuration de l'application since 5.1 Recréer par SSH sur chaque serveur → cipi.yml dans git, appliqué lors du déploiement
Hôte inconnu since 5.1 A atterri sur un vhost aléatoire → Serveur par défaut 444 vide
Déploiement interrompu since 5.1 Attendez quinze minutes pour un e-mail de santé → Sonde post-déploiement immédiate, restauration facultative
Alias since 5.1 Noms exacts uniquement → *.example.com caractères génériques

04 — Since 5.0.6

Panneau API, GUI
et l'automatisation.

Gestion du serveur à partir de REST API et Web GUI en option — ainsi que des indicateurs non interactifs pour les scripts. Nécessite cipi self-update à 5.1.0 et panneau API 1.20.

PHP Gestion des versions uniquement SSH → GET /api/php, installer, supprimer, définir par défaut
Clés SSH Administrateur de clé du terminal uniquement → REPOS + GUI pour cipi clés utilisateur
Prestations Système manuel → GET /api/services et redémarrez depuis le panneau
SMTP Assistant interactif uniquement → REPOS + cipi smtp configure --host=…
Santé Chèques CLI uniquement → REPOS par application + --json le CLI
Accès API N'importe quelle IP avec un jeton → Liste blanche IP facultative activée api/* et /mcp
Webhooks Recréer en rééditant le dépôt → cipi app webhook recreate [--rotate-secret]
Mise à jour automatique Pourrait s'accrocher à la marche API/GUI Composer → 5.0.14–5.0.17 — mises à jour programmées du panneau Packagist/tarball
Panneau GUI HTTP 500 après mise à niveau/mise à jour logicielle → 5.0.18 — pas de lien symbolique Composer à l'extérieur open_basedir

Une ligne se situe entre
toi et tout ça.

Exécutez le programme de mise à jour et Cipi reconstruit les hôtes virtuels, les pools, les modèles de déploiement et les métadonnées d'application en place – sans toucher à votre code ni à vos données.

  • Tout ce qui est nouveau est opt-in : Octane, Horizon, Reverb, PostgreSQL, instantanés, santé chèques, profils de sauvegarde, cipi.yml auto et la restauration après le déploiement reste désactivée jusqu'à ce que vous le demandiez.
  • Vos applications PHP-FPM continuent de fonctionner exactement telles quelles, à côté de tout nouveau Octane voisins.
  • Les nouveaux serveurs obtiennent tout cela immédiatement avec le programme d'installation habituel.
