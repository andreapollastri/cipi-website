Octane su FrankenPHP.
Oppure FPM classico. Decidi tu.

Ogni app sceglie il motore con un solo flag: Laravel Octane su FrankenPHP mantiene l'applicazione avviata in memoria e serve migliaia di richieste al secondo — oppure scegli PHP-FPM collaudato sul campo quando ti serve il classico. Dietro, MariaDB o PostgreSQL per app e Valkey per cache, sessioni e queue direttamente dalla memoria. Le prestazioni qui non sono un piano a pagamento. Sono lo script di installazione.

git push.
È tutta la pipeline.

Collega GitHub o GitLab una volta e Cipi fa il resto: deploy key generate e iniettate, webhook creati, ogni app provisionata con il proprio utente Linux, database, vhost e pool PHP-FPM. Fai push sul tuo branch e un deploy zero-downtime con verifica della firma parte in background — con rollback in un solo comando se ti serve. Nessun CI/CD da mantenere. Nessuna pipeline YAML da piangere.

deploy key automatiche webhook HMAC release zero-downtime rollback istantaneo
Come funzionano i deploy
YAML
cipi.yml

La configurazione che viaggia con il codice.

Un file committato accanto all'app: alias di dominio, versione PHP e php.ini, database extra, queue worker o Horizon, Laravel Reverb, lo scheduler, un healthcheck e i profili di backup. Generalo dal server, guarda il plan, applicalo — oppure fai opt-in così ogni deploy riuscito riallinea. Lo schema non contiene comandi shell; un file non valido viene rifiutato per intero, mai applicato a metà.

generate plan apply auto al deploy
Come funziona cipi.yml
Live
Sempre attivo

Queue, websocket, cron.
Già in esecuzione.

Horizon o queue worker semplici girano sotto Supervisor e si riavviano automaticamente a ogni deploy. Laravel Reverb spinge websocket realtime attraverso Nginx con SSL. Lo scheduler è collegato a cron nel momento in cui l'app viene creata. Job in background, broadcast e task schedulati non sono un ripensamento — fanno parte del provisioning.

AI
AI Native

La tua AI ha una linea diretta con la produzione.

Il server MCP integrato collega Cursor, VS Code o Claude Desktop direttamente alla tua app live via HTTPS. Fai domande in linguaggio naturale: leggi i log, esegui query SQL, lancia comandi artisan, attiva deploy. Le istruzioni distruttive sono bloccate, nessuna sessione SSH si apre mai, e non incolli più uno stack trace in una chat.

health app_info logs db_query artisan deploy
Scopri il server MCP
Sicuro
Fortezza

Hardened prima del tuo primo accesso.

Autenticazione SSH solo con chiave, Fail2ban con ban progressivi, firewall UFW, aggiornamenti di sicurezza automatici, un vault AES-256 per ogni credenziale, retention log conforme al GDPR e isolamento completo per utente Linux per app. Alert email su tentativi di intrusione, elevazioni sudo, modifiche alle chiavi SSH e deploy falliti — mentre tutto finisce in un log eventi a prova di manomissione. La sicurezza non è una funzionalità da attivare. È il default che dovresti lavorare per rimuovere.

solo chiave SSH Fail2ban + recidive UFW vault AES-256 alert in tempo reale
Il modello di sicurezza
Sync
Resilienza

Perdere un server ti costa un solo comando.

Codice, database, .env e storage — criptati e inviati a qualsiasi bucket compatibile S3 a intervalli programmati. Ripristina un database con un comando, torna indietro a una release con un altro. E quando è ora di migrare o recuperare, cipi sync clona app, database, config e certificati SSL su un server nuovo con un solo trasferimento criptato AES-256. Il disaster recovery smette di essere un progetto e diventa un comando.

Installazione in un solo comando

Un solo script trasforma un VPS Ubuntu nuovo in uno stack di produzione completo: Nginx, PHP 8.5, MariaDB o PostgreSQL, Valkey, Supervisor, Deployer, Certbot.

Octane su FrankenPHP

Approfondisci

MariaDB o PostgreSQL

MariaDB di default, PostgreSQL a un solo comando di distanza. Scegli il motore per app — .env e URL di connessione seguono automaticamente.

Approfondisci

Horizon & Reverb

App completamente isolate

Deploy zero-downtime

Approfondisci

Auto-deploy con git push
