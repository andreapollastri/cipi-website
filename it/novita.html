I titoli
01 — I titoli

Ventiquattro motivi per
aggiornare stasera.

Tutto ciò che aggiunge Cipi 5, a colpo d'occhio. Le tile since 5.0 sono arrivate con Cipi 5; since 5.2 è nuovo in questa release. Tocca una tile per saltare alla documentazione.

Funzionalità principale
01 since 5.0

Laravel Octane
su FrankenPHP.

Avvia il framework una volta e tienilo in memoria. App Octane e app PHP-FPM classiche girano affiancate sullo stesso server — Nginx fa proxy verso il processo Octane, Supervisor lo mantiene attivo, ogni deploy lo ricarica pulito.

cipi app create myapp --domain=myapp.com --octane
02 since 5.0

PostgreSQL, accanto a MariaDB.

Due motori su una macchina. Scegli per app o imposta un default a livello server — env, backup e ripristini seguono.

cipi db install pgsql
03 since 5.0

Laravel Horizon

Supervisionato e riavviato a ogni release.

cipi worker horizon enable
04 since 5.0

Laravel Reverb

WebSocket fatti per bene dalla 5.1.2: credenziali generate, wss:// dal certificato, un proxy che non intercetta più /appuntamenti.

cipi app reverb enable
05 since 5.0

La build frontend gira sul server

Esegui la build dentro la release, subito dopo le dipendenze. Fail-closed, così asset rotti non arrivano mai in produzione — e i file compilati non finiscono mai nel tuo repository.

cipi app edit myapp --node-build='npm ci && npm run build'
06 since 5.0

Switch scheduler

Cron attivo o disattivo per app, dalla CLI.

cipi schedule on myapp
07 since 5.0

Converti FPM ⇄ Octane

Cambia runtime su un'app live, in entrambe le direzioni.

cipi app convert myapp --to=octane
08 since 5.0

Uno snapshot prima di ogni migration rischiosa

Opt-in per app o per deploy e Cipi fa il dump del database prima che la release esca. Una migration sbagliata diventa recuperabile invece che fatale.

cipi deploy myapp --snapshot-required
09 since 5.0

Staging istantaneo

Clona un'app di produzione su un nuovo dominio.

cipi app clone myapp --domain=stage.myapp.com
10 since 5.0

Limiti risorse

Nessuna app può più affamare la macchina.

cipi app limits myapp --memory-limit=256M
11 since 5.0

Certificati wildcard, senza la danza HTTP

Emetti e rinnova tramite challenge DNS-01 Cloudflare quando un endpoint HTTP pubblico non è un'opzione. HTTP-01 resta il default.

cipi ssl install myapp --dns=cloudflare --wildcard
12 since 5.0

Health check

Ogni 5 minuti. Email dopo 3 fallimenti.

cipi health set myapp --url=…
13 since 5.0

Un host canonico

www o apex, alias e redirect 301 per te.

cipi www force-to-root myapp
14 since 5.0

Forza di nuovo HTTPS

Ripristina il redirect senza riemettere.

cipi ssl force myapp
15 since 5.1

Profili di backup, non un job hardcoded

Ambito, schedule, destinazione e retention per profilo. Una copia database locale ogni 30 minuti accanto a un backup completo cifrato notturno su S3. File e database archiviati separatamente; i database tenant scoperti dal motore. La retention è obbligatoria.

cipi backup profile add
16 since 5.1

php.ini guidato

Vedi ogni valore modificabile e quale layer lo ha impostato. Scrive FPM e CLI insieme, server-wide o --app=. Solo whitelist.

cipi ini set upload_max_filesize=50M
17 since 5.1

cipi.yml viaggia col codice

Alias, PHP, database extra, worker, healthcheck e backup — nel repo. plan, apply, auto dopo ogni deploy. Fail-closed: non crea mai un'app e non esegue mai un comando shell.

cipi yml generate myapp
18 since 5.1

Host sconosciuto → 444

Una richiesta che non matcha nessuna app finiva su un vhost a caso. Ora :80 e :443 la chiudono con una risposta vuota.

cipi nginx default-server on
19 since 5.1

Health post-deploy, rollback opzionale

La release appena pubblicata viene verificata subito — non dopo tre fallimenti da cinque minuti. Opt-in per il rollback automatico. Le migration non vengono annullate; l'email lo dice.

cipi health set myapp --rollback-on-unhealthy
20 since 5.1

Alias wildcard

Le app multi-tenant servono *.example.com. Nginx già poteva; ora Cipi lo accetta.

cipi alias add myapp '*.example.com'
Release sulla sicurezza
21 since 5.2

CrowdSec, engine
e bouncer.

Reputazione IP opt-in che legge i log che i tuoi vhost scrivono davvero. L'engine arriva con un bouncer firewall registrato, perché le decisioni senza bouncer non bannano niente. Si rifiuta di partire dietro un reverse proxy non configurato, e mette in allowlist la sessione SSH da cui lo abiliti. Nessun WAF.

cipi crowdsec enable
22 since 5.2

Una via per rientrare

Un listener TLS su porta alta e un token monouso. Una GET mette in allowlist il tuo IP e lo sbanna in CrowdSec e fail2ban. Non è un login, non è una chiave SSH.

cipi crowdsec rescue rotate
23 since 5.2

Controllo di integrità notturno

sha256 della release live contro il manifest scritto al deploy, poi ClamAV sulle sole directory di upload. Alle 04:40, ogni notte.

cipi scan enable
24 since 5.2

Completamento TAB, installato per te

bash e zsh, scritti da setup.sh e da ogni self-update. Verbi, sotto-comandi, flag e i nomi delle tue app. Nessun dotfile da modificare.

cipi app <TAB>

02 — Il cambiamento

Quello che prima era lavoro,
ora è un flag.

L'onesto prima e dopo. A sinistra cosa ti costava gestire queste cose. A destra Cipi 5, taggato per release.

Runtime since 5.0 PHP-FPM per tutto → FPM o Octane su FrankenPHP, scelto per app
Queue since 5.0 Queue worker nudi, riavviati a mano → Horizon sotto Supervisor, deploy-aware
Websocket since 5.0 Porta, proxy e servizio fai-da-te → Reverb attivabile in un comando, SSL incluso
Database since 5.0 MariaDB, prendi o lascia → MariaDB e PostgreSQL, per app
Frontend since 5.0 Commit degli asset compilati, o build in CI → Build Node dentro la release, fail-closed
Migration since 5.0 Deploy e spera → Snapshot automatico prima che la release esca
Staging since 5.0 Ricostruire una seconda app a mano → Un comando clone, database opzionale
Wildcard since 5.0 Challenge DNS manuale a ogni rinnovo → DNS-01 con Cloudflare, automatizzato
Monitoraggio since 5.0 Un servizio terzo e la sua fattura → Health check ogni cinque minuti, integrati
App rumorose since 5.0 Un'app poteva abbattere il server → Limiti rigidi su worker, figli e memoria
Backup since 5.1 Un job notturno hardcoded → Profili, AES-256 lato client, verify, cron gestito
php.ini since 5.1 Modifica a mano i file FPM; CLI ignorata → cipi ini per entrambi i SAPI, server-wide o per app
Config app since 5.1 Ricreare via SSH su ogni server → cipi.yml in git, applicato al deploy
Host sconosciuto since 5.1 Finiva su un vhost a caso → Default server 444 vuoto
Deploy rotto since 5.1 Aspettare quindici minuti per una mail di health → Probe post-deploy immediato, rollback opzionale
Alias since 5.1 Solo nomi esatti → Wildcard *.example.com
Attaccanti since 5.2 fail2ban, e solo a cose fatte → Decisioni CrowdSec scartate da un bouncer registrato
Chiuso fuori since 5.2 La console di rescue del provider → Token monouso su una porta TLS di rescue
Manomissioni since 5.2 Te ne accorgi quando qualcosa stona → sha256 notturno contro il manifest del deploy
La CLI since 5.2 Ricordarsi ogni verbo → Il TAB completa verbi, flag e nomi delle app

04 — Da 5.0.6

Panel API, GUI
e automazione.

Gestione server da REST API e web GUI opzionale — più flag non interattivi per script. Richiede cipi self-update a 5.1.0 e panel API 1.20.

PHP Solo da SSH → GET /api/php, install, remove, default di sistema
Chiavi SSH Admin solo da terminale → REST + GUI per le chiavi utente cipi
Servizi systemctl manuale → GET /api/services e restart dal pannello
SMTP Solo wizard interattivo → REST + cipi smtp configure --host=…
Health Check solo CLI → REST per app + --json in CLI
Accesso API Qualsiasi IP con token → IP whitelist opzionale su api/* e /mcp
Webhook Ricreare modificando il repo → cipi app webhook recreate [--rotate-secret]
Self-update Poteva bloccarsi su API/GUI Composer → 5.0.14–5.0.17 — update panel via Packagist/tarball
GUI pannello HTTP 500 dopo upgrade/soft update → 5.0.18 — niente symlink Composer fuori da open_basedir

Una riga ti separa
da tutto questo.

Esegui l'updater e Cipi ricostruisce vhost, pool, template Deployer e metadata delle app sul posto — senza toccare codice o dati.

  • Tutto il nuovo è opt-in — Octane, Horizon, Reverb, PostgreSQL, snapshot, health check, profili di backup, cipi.yml auto e rollback post-deploy, CrowdSec e lo scan notturno restano disattivati finché non li chiedi.
  • Le tue app PHP-FPM continuano a girare esattamente come sono, accanto ai nuovi vicini Octane.
  • I server nuovi ottengono tutto già incluso con l'installer abituale.
