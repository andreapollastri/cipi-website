The headlines
01 — Os destaques

Vinte e quatro razões para
atualizar esta noite.

Tudo o que Cipi 5 acrescenta, num piscar de olhos. Blocos marcados since 5.0 vieram com o Cipi 5; since 5.2 é novo nesta versão. Toque em qualquer bloco para acessar os documentos.

Headline feature
01 since 5.0

Laravel Octane
on FrankenPHP.

Inicialize o framework uma vez e mantenha-o na memória. Octane aplicativos e aplicativos PHP-FPM clássicos são executados lado a lado no mesmo servidor — Nginx faz proxy do processo Octane, Supervisor o mantém vivo, cada deploy o recarrega de forma limpa.

cipi app create myapp --domain=myapp.com --octane
02 since 5.0

PostgreSQL, alongside MariaDB.

Dois motores em uma caixa. Escolha por aplicativo ou defina um padrão para todo o servidor – ambiente, backups e as restaurações seguem.

cipi db install pgsql
03 since 5.0

Laravel Horizon

Supervisionado e reiniciado em cada versão.

cipi worker horizon enable
04 since 5.0

Laravel Reverb

WebSockets prontos desde 5.1.2: credenciais geradas, wss:// a partir do certificado, um proxy que já não engole /appointments.

cipi app reverb enable
05 since 5.0

O build do seu frontend acontece no servidor

Execute o build dentro do release, logo após as dependências. Ativos falidos e quebrados nunca chegue à produção — e os arquivos compilados nunca cheguem ao seu repositório.

cipi app edit myapp --node-build='npm ci && npm run build'
06 since 5.0

Scheduler switch

Cron ligado ou desligado por app, direto da CLI.

cipi schedule on myapp
07 since 5.0

Converter FPM ⇄ Octane

Alterne o tempo de execução em um aplicativo ativo, nos dois sentidos.

cipi app convert myapp --to=octane
08 since 5.0

Um snapshot antes de cada migração arriscada

Ative por aplicativo ou por deploy e Cipi despeja o banco de dados antes do lançamento. Um mau a migração torna-se recuperável em vez de fatal.

cipi deploy myapp --snapshot-required
09 since 5.0

Instant staging

Clone um aplicativo de produção em um novo domínio.

cipi app clone myapp --domain=stage.myapp.com
10 since 5.0

Resource limits

Nenhuma app consegue mais sufocar a máquina.

cipi app limits myapp --memory-limit=256M
11 since 5.0

Certificados wildcard, sem a dança HTTP

Emita e renove por meio de um desafio Cloudflare DNS-01 quando um endpoint HTTP público não for um opção. HTTP-01 permanece o padrão.

cipi ssl install myapp --dns=cloudflare --wildcard
12 since 5.0

Health checks

A cada 5 minutos. Email após 3 falhas.

cipi health set myapp --url=…
13 since 5.0

One canonical host

www ou apex, alias e 301 para você.

cipi www force-to-root myapp
14 since 5.0

Re-force HTTPS

Restaura o redirecionamento sem reemitir o certificado.

cipi ssl force myapp
15 since 5.1

Perfis de backup, em vez de um único job fixo

Escopo, cronograma, destino e retenção por perfil. A seguir, uma cópia do banco de dados local de 30 minutos para uma cópia completa noturna criptografada em S3. Arquivos e bancos de dados armazenados separadamente; inquilino bancos de dados descobertos no mecanismo. A retenção é obrigatória.

cipi backup profile add
16 since 5.1

Guided php.ini

Veja cada ajuste e qual camada o define. Grava FPM e CLI juntos, em todo o servidor ou --app=. Whitelist only.

cipi ini set upload_max_filesize=50M
17 since 5.1

cipi.yml travels with the code

Aliases, PHP, bancos de dados extras, workers, verificação de integridade e backups — no repositório. plan, apply, auto após cada deploy. Fechado com falha: ele nunca cria um aplicativo e nunca executa um comando shell.

cipi yml generate myapp
18 since 5.1

Host desconhecido → 444

Uma solicitação que não corresponde a nenhum aplicativo usado para chegar a um vhost aleatório. Agora :80 e :443 encerre com uma resposta vazia.

cipi nginx default-server on
19 since 5.1

Health check pós-deploy, rollback opcional

O lançamento que acabou de ir ao ar é investigado imediatamente - não depois de três minutos de cinco falhas. Ative para reverter automaticamente. As migrações não são desfeitas; o e-mail diz então.

cipi health set myapp --rollback-on-unhealthy
20 since 5.1

Wildcard aliases

Multi-tenant apps need *.example.com. Nginx já poderia; Cipi agora aceita isso.

cipi alias add myapp '*.example.com'
Versão de segurança
21 since 5.2

CrowdSec, motor
e bouncer.

Reputação de IP opcional que lê os logs que os teus vhosts escrevem de facto. O motor vem com um bouncer de firewall registado, porque decisões sem bouncer não banem nada. Recusa arrancar atrás de um proxy inverso não configurado, e coloca na allowlist a sessão SSH a partir da qual o ativas. Não há WAF.

cipi crowdsec enable
22 since 5.2

Um caminho de volta

Um listener TLS num porto alto e um token de uso único. Um GET coloca o teu IP na allowlist e desbane-o no CrowdSec e no fail2ban. Nem login, nem chave SSH.

cipi crowdsec rescue rotate
23 since 5.2

Verificação de integridade noturna

sha256 da release viva contra o manifesto escrito no deploy, e depois ClamAV apenas sobre as diretorias de uploads. Às 04:40, todas as noites.

cipi scan enable
24 since 5.2

Completação TAB, instalada por ti

bash e zsh, escritas pelo setup.sh e por cada self-update. Verbos, subcomandos, flags e os nomes das tuas apps. Nenhum dotfile para editar.

cipi app <TAB>

02 — A virada

O que antes dava trabalho,
agora é uma flag.

O honesto antes e depois. À esquerda está o que custava administrar essas coisas. À direita é Cipi 5, marcado por lançamento.

Runtime since 5.0 PHP-FPM for everything → FPM ou Octane em FrankenPHP, escolhido por app
Queues since 5.0 Workers de fila crus, reiniciados à mão → Horizon em Supervisor, com reconhecimento de deploy
Websockets since 5.0 Você mesmo cuidava da porta, do proxy e do serviço → Reverb ativado em um comando, SSL incluído
Databases since 5.0 MariaDB, é isso ou nada → MariaDB e PostgreSQL, per app
Frontend since 5.0 Commitar assets compilados, ou buildar no CI → A compilação do nó é executada dentro da versão, fechada com falha
Migrations since 5.0 Deploy and hope → Snapshot automático antes do lançamento ser lançado
Staging since 5.0 Recriar uma segunda app à mão → Um comando de clone, banco de dados opcional
Wildcards since 5.0 Desafio DNS manual a cada renovação → DNS-01 com Cloudflare, automatizado
Monitoring since 5.0 Um serviço de terceiros e a fatura dele → Verificações de integridade a cada cinco minutos, integradas
Noisy apps since 5.0 Uma app conseguia derrubar o servidor → Limitações rígidas para workers, crianças e memória
Backups since 5.1 Um único job noturno fixo no código → Perfis, lado do cliente AES-256, verificação, gerenciado cron
php.ini since 5.1 Editar os arquivos do FPM à mão; a CLI era ignorada → cipi inipara ambos SAPIs, em todo o servidor ou por aplicativo
App config since 5.1 Recriar por SSH em cada servidor → cipi.yml no git, aplicado no deploy
Unknown Host since 5.1 Caía num vhost aleatório → Servidor padrão 444 vazio
Broken deploy since 5.1 Aguarde quinze minutos por um e-mail sobre saúde → Sondagem pós-deploy imediata, reversão opcional
Aliases since 5.1 Exact names only → *.example.com wildcards
Atacantes since 5.2 fail2ban, e só depois do facto → Decisões do CrowdSec descartadas por um bouncer registado
Fechado fora since 5.2 A consola de resgate do fornecedor → Token de uso único num porto TLS de resgate
Adulteração since 5.2 Dás por isso quando algo destoa → sha256 noturno contra o manifesto do deploy
A CLI since 5.2 Decorar cada verbo → O TAB completa verbos, flags e nomes de apps

04 — Desde a 5.0.6

Panel API, GUI
and automation.

Gerenciamento de servidor a partir do REST API e web opcional GUI — além de sinalizadores não interativos para scripts. Requer cipi self-update para 5.1.0 and panel API 1.20.

PHP SSH-only version management → GET /api/php, install, remove, definir padrão
Chaves SSH Terminal-only key admin → REST + GUI para cipi user keys
Serviços Manual systemctl → GET /api/services e reiniciar pelo painel
SMTP Interactive wizard only → REST + cipi smtp configure --host=…
Saúde CLI-only checks → REST por app + --json on CLI
API access Qualquer IP com um token → Lista de IPs permitidos opcional em api/* e /mcp
Webhooks Recriar reeditando o repositório → cipi app webhook recreate [--rotate-secret]
Self-update Podia travar no passo do Composer da API/GUI → 5.0.14–5.0.17— atualizações cronometradas do painel Packagist/tarball
Panel GUI HTTP 500 depois do upgrade/soft update → 5.0.18 — sem symlink do Composer fora open_basedir

Uma linha separa
você e tudo isso.

Execute o atualizador e Cipi reconstrói vhosts, pools, modelos de Deployer e metadados de aplicativos no local — sem tocar no seu código ou nos seus dados.

  • Tudo o que é novo é opcional – Octane, Horizon, Reverb, PostgreSQL, snapshots, saúde verificações, perfis de backup, cipi.yml auto a reversão pós-deploy, o CrowdSec e o scan noturno permanecem desativados até você perguntar.
  • Seus aplicativos PHP-FPM continuam funcionando exatamente como estão, próximos a qualquer novo Octane vizinhos.
  • Servidores novos tiram tudo da caixa com o instalador usual.
