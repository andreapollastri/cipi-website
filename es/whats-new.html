Los titulares
01 — Los titulares

Veinticuatro razones para
actualizar esta noche.

Todo lo que suma Cipi 5, de un vistazo. Azulejos etiquetados since 5.0 enviado con Cipi 5; since 5.2 es nuevo en esta versión. Toque cualquier mosaico para acceder a los documentos.

Característica principal
01 since 5.0

Laravel Octane
en FrankenPHP.

Arranca el framework una vez y mantenlo en memoria. Las apps con Octane y las apps PHP-FPM clásicas conviven en el mismo servidor: Nginx hace de proxy hacia el proceso de Octane, Supervisor lo mantiene vivo y cada despliegue lo recarga limpiamente.

cipi app create myapp --domain=myapp.com --octane
02 since 5.0

PostgreSQL, junto a MariaDB.

Dos motores en la misma máquina. Elige por app o define un valor por defecto para todo el servidor: el .env, los backups y las restauraciones se adaptan solos.

cipi db install pgsql
03 since 5.0

Laravel Horizon

Supervisado y reiniciado en cada lanzamiento.

cipi worker horizon enable
04 since 5.0

Laravel Reverb

WebSockets listos desde 5.1.2: credenciales generadas, wss:// según el certificado, un proxy que ya no se traga /appointments.

cipi app reverb enable
05 since 5.0

Su interfaz se basa en el servidor

Ejecuta el build dentro de la release, justo después de las dependencias. Falla en cerrado, así los assets rotos nunca llegan a producción — y los archivos compilados nunca llegan a tu repositorio.

cipi app edit myapp --node-build='npm ci && npm run build'
06 since 5.0

cambio de programador

Cron activado o desactivado por aplicación, desde CLI.

cipi schedule on myapp
07 since 5.0

Convertir FPM ⇄ Octane

Cambie el tiempo de ejecución en una aplicación en vivo, en ambos sentidos.

cipi app convert myapp --to=octane
08 since 5.0

Un snapshot antes de cada migración arriesgada

Actívalo por app o por despliegue y Cipi volcará la base de datos antes de publicar la release. Una migración mala pasa de fatal a recuperable.

cipi deploy myapp --snapshot-required
09 since 5.0

Staging instantáneo

Clona una aplicación de producción en un nuevo dominio.

cipi app clone myapp --domain=stage.myapp.com
10 since 5.0

Límites de recursos

Ya ninguna aplicación puede matar de hambre a la caja.

cipi app limits myapp --memory-limit=256M
11 since 5.0

Certificados wildcard, sin el baile HTTP

Emite y renueva con un desafío DNS-01 de Cloudflare cuando no puedes exponer un endpoint HTTP público. HTTP-01 sigue siendo el valor por defecto.

cipi ssl install myapp --dns=cloudflare --wildcard
12 since 5.0

Controles de salud

Cada 5 minutos. Correo electrónico después de 3 fallos.

cipi health set myapp --url=…
13 since 5.0

Un anfitrión canónico

www o apex, con alias y 301 para usted.

cipi www force-to-root myapp
14 since 5.0

Reforzar HTTPS

Restaura la redirección sin volver a emitirla.

cipi ssl force myapp
15 since 5.1

Perfiles de respaldo, ni un trabajo codificado

Alcance, programación, destino y retención por perfil. Una copia local de la base de datos cada 30 minutos junto a una copia completa nocturna y cifrada en S3. Los archivos y las bases de datos se guardan por separado; las bases de datos de cada tenant se descubren desde el motor. La retención es obligatoria.

cipi backup profile add
16 since 5.1

Guiado php.ini

Vea cada sintonizable y qué capa lo configuró. Escribe FPM y CLI juntos, en todo el servidor o--app=. Solo lista blanca.

cipi ini set upload_max_filesize=50M
17 since 5.1

cipi.yml viaja con el código

Alias, PHP, bases de datos adicionales, workers, health check y copias de seguridad, en el repositorio.plan, apply, auto después de cada despliegue. Falla en cerrado: nunca crea una app ni ejecuta un comando de shell.

cipi yml generate myapp
18 since 5.1

Anfitrión desconocido → 444

Una solicitud que no coincide con ninguna aplicación solía aterrizar en un host virtual aleatorio. ahora :80 y :443 ciérrelo con una respuesta vacía.

cipi nginx default-server on
19 since 5.1

Estado posterior a la despliegue, reversión opcional

La release que acaba de entrar en producción se comprueba de inmediato, no después de tres fallos de cinco minutos. Puedes activar el rollback automático. Las migraciones no se deshacen, y el correo lo avisa.

cipi health set myapp --rollback-on-unhealthy
20 since 5.1

Alias wildcard

Las aplicaciones multiinquilino necesitan *.example.com. Nginx ya pudo; Cipi ahora acepta eso.

cipi alias add myapp '*.example.com'
Release de seguridad
21 since 5.2

CrowdSec, motor
y bouncer.

Reputación de IP opcional que lee los logs que tus vhosts escriben de verdad. El motor viene con un bouncer de firewall registrado, porque las decisiones sin bouncer no banean nada. Se niega a arrancar detrás de un proxy inverso sin configurar, y añade a la allowlist la sesión SSH desde la que lo activas. No hay WAF.

cipi crowdsec enable
22 since 5.2

Una vía de vuelta

Un listener TLS en un puerto alto y un token de un solo uso. Un GET añade tu IP a la allowlist y la desbanea en CrowdSec y fail2ban. Ni login ni clave SSH.

cipi crowdsec rescue rotate
23 since 5.2

Comprobación de integridad nocturna

sha256 de la release viva contra el manifiesto escrito en el deploy, y luego ClamAV solo sobre los directorios de subidas. A las 04:40, cada noche.

cipi scan enable
24 since 5.2

Autocompletado, instalado por ti

bash y zsh, escritos por setup.sh y por cada self-update. Verbos, subcomandos, flags y los nombres de tus apps. Ningún dotfile que editar.

cipi app <TAB>

02 — El cambio

Lo que antes era trabajo
Ahora es una bandera.

El antes y el después honesto. Lo que queda es lo que solía costarle ejecutar estas cosas. La derecha es Cipi 5, etiquetado por lanzamiento.

Runtime since 5.0 PHP-FPM para todo → FPM o Octane en FrankenPHP, elegido por aplicación
Colas since 5.0 Workers de cola desnudos, reiniciados a mano → Horizon bajo Supervisor, compatible con despliegue
enchufes web since 5.0 Implemente su propio puerto, proxy y servicio → Reverb habilitado en un comando, SSL incluido
Bases de datos since 5.0 MariaDB, tómalo o déjalo → MariaDB y PostgreSQL, por aplicación
Interfaz since 5.0 Confirmar activos compilados o incorporar CI → La compilación del nodo se ejecuta dentro de la versión, cerrada ante fallos
Migraciones since 5.0 Implementar y esperar → Snapshot automática antes de que salga el lanzamiento.
Puesta en escena since 5.0 Reconstruir una segunda aplicación a mano → Un comando de clonación, base de datos opcional
comodines since 5.0 Manual DNS desafía cada renovación → DNS-01 con Cloudflare, automatizado
Monitoreo since 5.0 Un servicio de terceros y su factura → Controles de salud cada cinco minutos, integrados
Aplicaciones ruidosas since 5.0 Una aplicación podría provocar la caída del servidor → Límites estrictos para los workers, los niños y la memoria
Copias de seguridad since 5.1 Un trabajo nocturno codificado → Perfiles, lado del cliente AES-256, verificar, administrado cron
php.ini since 5.1 Edición manual de archivos FPM; CLI ignorado → cipi ini para ambos SAPI, en todo el servidor o por aplicación
Configuración de la aplicación since 5.1 Recrear por SSH en cada servidor → cipi.yml en git, aplicado en la despliegue
Anfitrión desconocido since 5.1 Aterrizó en un vhost aleatorio → Servidor predeterminado 444 vacío
Despliegue roto since 5.1 Espere quince minutos para recibir un correo electrónico de salud. → Sondeo inmediato posterior a la despliegue, reversión opcional
Alias since 5.1 Solo nombres exactos → *.example.com comodines
Atacantes since 5.2 fail2ban, y solo a toro pasado → Decisiones de CrowdSec descartadas por un bouncer registrado
Sin acceso since 5.2 La consola de rescate del proveedor → Token de un solo uso en un puerto TLS de rescate
Manipulación since 5.2 Te enteras cuando algo chirría → sha256 nocturno contra el manifiesto del deploy
La CLI since 5.2 Recordar cada verbo → TAB completa verbos, flags y nombres de app

04 — Desde la 5.0.6

Paneles API, GUI
y automatización.

Gestión del servidor desde la REST API y la GUI web opcional, más flags no interactivos para scripts. Requiere cipi self-update a 5.1.0 y panel API 1.20.

PHP Gestión de versiones solo SSH → GET /api/php, instalar, quitar, establecer por defecto
Claves SSH Administrador de claves solo de terminal → REST + GUI para cipi claves de usuario
Servicios sistema manualctl → GET /api/services y reiniciar desde el panel
SMTP Solo asistente interactivo → REST + cipi smtp configure --host=…
Salud Cheques solo CLI → REST por aplicación + --json en CLI
API acceso Cualquier IP con un token → Lista blanca de IP opcional activada api/* y /mcp
Ganchos web Recrear reeditando el repositorio → cipi app webhook recreate [--rotate-secret]
Autoactualización Podría aguantar en API/GUI Composer paso → 5.0.14–5.0.17 — actualizaciones cronometradas del panel Packagist/tarball
Panel GUI HTTP 500 después de la actualización/actualización de software → 5.0.18 — no hay enlace simbólico Composer afuera open_basedir

Una línea se interpone entre
tú y todo eso.

Ejecuta el actualizador y Cipi reconstruye vhosts, pools, plantillas de Deployer y metadatos de las apps en su sitio, sin tocar tu código ni tus datos.

  • Todo lo nuevo es opcional: Octane, Horizon, Reverb, PostgreSQL, snapshots, health checks, perfiles de backup, cipi.yml autola reversión post-deploy, CrowdSec y el escaneo nocturno permanecen desactivados hasta que lo pidas.
  • Tus apps PHP-FPM siguen funcionando exactamente igual, al lado de cualquier vecina nueva con Octane.
  • Los servidores nuevos lo obtienen todo de inmediato con el instalador habitual.
