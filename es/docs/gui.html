Panel de control (GUI)

El panel de control web opcional

Cipi es, y siempre será, CLI-primero. Todo lo que un servidor necesita: aplicaciones, bases de datos, SSL, implementaciones, copias de seguridad, firewall: es un único cipi comando de distancia a través de SSH. pero de v4.7.0 Cipi también envía un opcional panel de control web: un self-hosted Laravel panel que gestiona uno o más Cipi servidores desde el navegador, sobre el mismo DESCANSO API el cliente CLI y el uso del módulo WHMCS.

100% opcional.El panel es un paquete independiente que usted instala sólo si lo desea eso. Sáltelo y Cipi se ejecutará exactamente como antes: un CLI sencillo sin demonio, sin superficie web y nada extra escuchando. Instálalo y tu equipo o clientes obtendrán una interfaz de usuario amigable sin darse por vencido la terminal. Tu servidor, tu elección.

El panel es una delgada capa visual encima del API; no reemplaza al CLI ni agrega una característica patentada. plano de mando. Todo lo que hagas en el navegador, aún podrás hacerlo desde el terminal, y viceversa. Un solo panel puede controlar muchos servidores, por lo que también funciona como una cabina liviana para múltiples servidores.

Qué puedes hacer desde el panel

  • Administrar aplicaciones — crear, editar, implementar, suspender/reanudar y eliminar Laravel y aplicaciones personalizadas; administrar alias, redirecciones WWW/apex, SSL (instalar + forzar HTTPS) y HTTP básico autentificación.
  • Crea Laravel aplicaciones con opción Laravel Octane (FrankenPHP) (API 1.13+ / Cipi 5.0+); Las vistas de lista y detalle muestran FPM vs. Octane.
  • Editar aplicación .env, gestionar Composer auth.json, correr Artisany ejecutar en la lista blanca Comandos de aplicaciones (cipi app run) — requiere API 1.14+ / Cipi 5.0.3+ (La salida del terminal admite Markdown copia).
  • Elige una base de datos motor en la creación de la aplicación (mariadb o pgsql) y gestionar bases de datos multimotor (API 1.12+ / Cipi 4.8+).
  • Explorar aplicaciones y servidores registros con filtro de tipo, paginación y actualización automática.
  • ver trabajos asíncronos en una superposición interactiva (spinner + salida de terminal mientras sondeo GET /api/jobs/{id}).
  • en vivo tablero — CPU, memoria, disco, servicios y recuento de aplicaciones a través de GET /api/status.
  • Cabina de servidor (API 1.15+ / Cipi 5.0.6+) — administrar PHP versiones y valores predeterminados del sistema, claves SSH, servicios, notificaciones SMTP, HTTP comprobaciones de estado y lista blanca de IP del panel API desde el navegador.
  • Regístrate y cambia entre múltiples servidores desde un inicio de sesión.

Panel de control (GUI)

Requisitos

El panel habla con sus servidores exclusivamente a través del Cipi REST API. Antes de instalarlo, asegúrese Cada servidor que deseas administrar tiene el API habilitado con un token que cubre el conjunto completo de habilidades.

Cada servidor administrado necesitacipi api instalado y un Ficha de portador con todas las habilidades. Ver el API guía de configuración a generar uno.
  • Un servidor Cipi en ejecución (Ubuntu 24.04 / 26.04) para alojar el panel; este puede ser uno de los servidores gestionas o una pequeña caja dedicada.
  • Un dominio (o subdominio) apuntado a ese servidor, p.e. panel.example.com.
  • cipi api habilitado en cada servidor que desee controlar, cada uno con una capacidad total ficha (incluye www-manage, status-viewy para herramientas de aplicaciones apps-env, apps-auth, apps-artisan, apps-run, apps-deploy-config). Para cabina de servidor (PHP, SSH, servicios, SMTP, estado, lista blanca de IP), los servidores administrados necesitan API 1.15+ y Cipi 5.0.6+. Para .env / auth.json / Artisan / App commands, managed servers need API 1.14+ y Cipi 5.0.3+. Para Octane crear y Indicadores FPM/Octane, API 1.13+ y Cipi 5.0+. Para multimotor MariaDB/PostgreSQL y redirecciones www, API 1.12+ y Cipi 4.8+.

El instalador proporciona PHP, el grupo FPM, Nginx vhost y el programador. no configura un entorno Laravel manualmente.

Panel de control (GUI)

Instalación — cipi gui <domain>

Un comando aprovisiona todo el panel en un servidor Cipi: un grupo dedicado de PHP-FPM, un vhost Nginx para su dominio y un trabajo de programador cron. La aplicación Laravel está incluida en /opt/cipi/gui, el mismo modelo utilizado por el cipi-api paquete.

fiesta
cipi gui panel.example.com

El instalador solicita de forma interactiva la primera cuenta de administrador: un correo electrónico y una contraseña. La contraseña debe cumplir con la política del panel:

  • Mínimo 12 caracteres.
  • Al menos una mayúscula, una minúscula, un dígito y un carácter especial.
  • No más que 4 idénticos consecutivos personajes.

La configuración se escribe en /etc/cipi/gui.json. Una vez que finalice el comando, abra su dominio en un navegador e inicie sesión con la cuenta de administrador que acaba de crear.

El panel se entrega sobre HTTP simple hasta que se emite un certificado. correr cipi gui ssl inmediatamente después de la instalación para asegurarlo.

Panel de control (GUI)

SSL — cipi gui ssl

Emita un certificado Let's Encrypt gratuito para el dominio del panel y cámbielo a HTTPS. El panel es HTTPS-aware y establece los encabezados reenviados correctos detrás del Cipi Nginx vhost.

fiesta
cipi gui ssl

El certificado se renueva automáticamente mediante la misma renovación ACME que Cipi utiliza para los dominios de aplicaciones.

Panel de control (GUI)

Autenticación de dos factores (TOTP)

El panel utiliza el inicio de sesión clásico y admite TOTP opcional de dos factores autenticación. Cada administrador puede inscribir una aplicación de autenticación (Google Authenticator, 1Password, Aegis,…) de su perfil. 2FA es una opción voluntaria por usuario, no obligatoria.

Si un administrador pierde el acceso a su segundo factor, un operador con acceso de shell puede borrarlo desde el servidor concipi gui reset-user, que reescribe la cuenta y elimina la inscripción 2FA.

Panel de control (GUI)

Actualizando — gui update vs gui upgrade

El panel se envía como el cipi/gui Paquete Composer, por lo que las actualizaciones son normales Composer actualizaciones más migraciones. Dos comandos cubren los casos comunes:

cipi gui update - actualización suave

Corre composer update cipi/gui, aplica migraciones de bases de datos y actualiza el archivo compilado. tema. Esta es la ruta de actualización diaria.

fiesta
cipi gui update

cipi gui upgrade - reconstrucción completa

Reconstruye el panel desde cero. Úselo después de un lanzamiento importante, o si un entorno ha cambiado y un La reinstalación limpia del código de la aplicación es la forma más rápida de regresar a un estado en buen estado.

fiesta
cipi gui upgrade

cipi gui refresh-theme - solo tema

Recompila y recarga el tema del panel sin tocar el código o la base de datos, lo cual resulta útil después de un tema. retocar.

fiesta
cipi gui refresh-theme

Panel de control (GUI)

Operaciones

cipi gui status

Informe el estado actual del panel: si está instalado, su dominio y el estado de su servicios.

fiesta
cipi gui status

cipi gui fix-permissions

Reparar el PHP-FPM del panel open_basedir restricción y todos los permisos de archivos en tiempo de ejecución. Ejecútelo si el panel comienza a generar errores de permiso o de carga automática después de una actualización, incluido el HTTP 500 después cipi gui upgrade / soft update fixed in 5.0.18 (enlace simbólico Composer para cipi/gui afuera open_basedir).

fiesta
cipi gui fix-permissions

cipi gui reset-user

Vuelva a escribir el correo electrónico, el nombre y la contraseña de un administrador y borre su inscripción 2FA: la ruta de recuperación cuando alguien está bloqueado.reset-password es un alias para el mismo comando.

fiesta
cipi gui reset-user

Panel de control (GUI)

Quitar el panel— cipi gui remove

Desinstale el panel y su Nginx vhost, PHP-FPM y su programador. Tus servidores y aplicaciones son intacto: el panel es solo un cliente del API. uninstalles un alias, y --force omite el mensaje de confirmación.

fiesta
cipi gui remove
cipi gui remove --force

Quitar el panel es la máxima expresión de su opcionalidad: desinstálalo en cualquier momento y Cipi es de nuevo a un CLI puro, exactamente como era antes.

API cobertura

El GUI consume toda la superficie Cipi API OpenAPI. Mantenga el panel y cada servidor administrado cipi/api paquete actual (cipi gui update / cipi api update) para crear formularios y enumerar campos que coincidan con el servidor.
